# API и MCP

Всё, что умеет веб-панель, доступно по HTTP API. ИИ-агенты (Claude, Cursor и другие) подключаются
к той же базе через MCP-сервер, встроенный в панель.

## Токены

Токены создаются в панели: **Настройки → API-токены → Создать токен**. Токен показывается один раз,
в базе хранится только его SHA-256.

| Права | Что можно |
|---|---|
| Только чтение | Любые `GET`-запросы: поиск, профили, аналитика, выгрузки. MCP — все инструменты чтения. |
| Полный доступ | Всё, кроме управления токенами: метки, заметки, метаданные, PDF, запуск сборов от имени Telegram-аккаунта. |

Срок действия можно ограничить: 30 дней, 90 дней или год. Отозванный или истёкший токен сразу
перестаёт работать. В списке токенов видно, когда каждым пользовались в последний раз.

Создавать и отзывать токены можно только из панели после входа по паролю. Токеном выпустить
новый токен нельзя.

## HTTP API

Токен передаётся в заголовке:

```bash
curl -H "Authorization: Bearer tgt_…" "https://panel.example.com/api/users?limit=5"
```

**Документация:** `/api/docs` (Scalar), в боковом меню панели это пункт «API-документация».
Схема OpenAPI 3.1 лежит в `/api/openapi.json`. Обе страницы закрыты логином панели. В Scalar можно
вставить токен в поле *Bearer Token* и выполнять запросы прямо со страницы. Облачные функции Scalar
(Share, Deploy, AI-чат, телеметрия) отключены, так что спецификация никуда не отправляется.

Полезные эндпоинты для старта:

| Запрос | Что вернёт |
|---|---|
| `GET /api/overview` | Сводка по базе |
| `GET /api/sources` | Источники: каналы и чаты |
| `GET /api/users?search=…` | Люди. Поиск по имени, @username, ID, заметке, метаданным и тексту PDF |
| `GET /api/users/{id}` | Профиль человека с метаданными и списком PDF |
| `GET /api/search/messages?q=…` | Полнотекстовый поиск по сообщениям |
| `GET /api/search/people?q=…` | Поиск людей по метаданным и PDF |
| `GET /api/users?format=xlsx` | Выгрузка; `format` работает почти у всех списков |

## MCP-сервер

Адрес: `https://<ваша-панель>/mcp`. Транспорт Streamable HTTP, сервер работает без сессий
(stateless), поэтому подходит любой reverse proxy. Авторизация — тот же API-токен в заголовке
`Authorization: Bearer tgt_…`.

Готовые конфигурации с вашим адресом есть в панели: **Настройки → MCP для ИИ-агентов**. Если создать
токен на этой же странице, он подставится в них автоматически.

**Claude Code:**

```bash
claude mcp add --transport http tg-toolkit https://panel.example.com/mcp --header "Authorization: Bearer tgt_…"
```

**Cursor, Windsurf, VS Code** и другие клиенты с поддержкой HTTP-серверов:

```json
{
  "mcpServers": {
    "tg-toolkit": {
      "url": "https://panel.example.com/mcp",
      "headers": { "Authorization": "Bearer tgt_…" }
    }
  }
}
```

**Claude Desktop** через [mcp-remote](https://www.npmjs.com/package/mcp-remote) (нужен Node.js), в `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "tg-toolkit": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://panel.example.com/mcp", "--header", "Authorization:Bearer tgt_…"]
    }
  }
}
```

### Инструменты

**Чтение** (достаточно токена «только чтение»):

| Инструмент | Что делает |
|---|---|
| `overview` | Сводка по базе: источники, люди, сообщения, самые активные |
| `list_sources`, `source_analytics` | Источники и аналитика одного из них |
| `audience_overlap`, `overlap_people` | Пересечения аудиторий и люди, которые есть в нескольких источниках |
| `search_messages`, `get_message_context` | Полнотекстовый поиск по сообщениям и контекст вокруг найденного |
| `search_people` | Поиск людей по метаданным и тексту PDF |
| `list_users`, `get_user_profile` | Список людей с фильтрами и профиль одного человека |
| `get_user_messages`, `get_user_connections` | Сообщения человека; с кем он пересекается и переписывается |
| `get_user_file_text` | Текст PDF, прикреплённого к профилю |
| `list_tags`, `list_found_channels` | Метки; каналы, найденные через людей |
| `list_jobs`, `get_job`, `list_accounts` | Задачи сбора и их прогресс; подключённые аккаунты |

**Изменения** (нужен полный доступ): `update_user_note` (метки, заметка, избранное, игнор) и
`update_user_metadata` (ФИО, email, телефон, страна, город, адрес, паспорт).

**Запросы в Telegram** (нужен полный доступ): `preview_link`, `collect_channel_comments`, `index_chat`,
`rerun_source`, `find_user_channels`. Они работают от имени подключённого Telegram-аккаунта и
расходуют его лимиты. В описаниях инструментов агенту сказано запускать их только по просьбе
пользователя.

Агенту стоит выдавать токен «только чтение», если ему не нужно ничего менять. Тексты сообщений
пишут пользователи Telegram, и сервер предупреждает агента, что это данные, а не инструкции.

### Проверка без клиента

```bash
curl -s https://panel.example.com/mcp \
  -H "Authorization: Bearer tgt_…" \
  -H "Accept: application/json, text/event-stream" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

## Безопасность

- Без HTTPS токен передаётся открытым текстом. Публикуйте панель только через reverse proxy с TLS,
  см. [deployment.md](deployment.md).
- Метаданные людей хранятся в базе без шифрования, иначе по ним не работал бы поиск. Защищайте
  доступ к панели и к тому `/data`.
- Утёкший токен отзывается в настройках. Действует сразу, перезапуск не нужен.
