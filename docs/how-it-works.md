# Как это устроено в Telegram

TG Toolkit работает через **MTProto** (библиотека [Telethon](https://github.com/LonamiWebs/Telethon)) от имени
обычного пользовательского аккаунта. Bot API для этой задачи не подходит: бот не может читать историю
чужих каналов и групп.

## Каналы и комментарии

- Канал (broadcast) сам комментарии не хранит. У него есть **связанная группа обсуждений** (`ChannelFull.linked_chat_id`).
- Каждый пост автоматически пересылается в эту группу. Копия с `fwd_from.channel_post` становится корнем треда.
- Комментарий — это сообщение группы с `reply_to` на корень. У ответов на ответы корень лежит в `reply_to_top_id`.
- Остальные сообщения группы — обычный чат, комментариями они не считаются.
- Пишет «от имени канала» (`PeerChannel`) или анонимный админ? Тогда автор учитывается и помечается отдельно.

Режимы сбора:

| Режим | Как | Когда |
|---|---|---|
| **Быстрый** | Один проход по истории группы, ~100 сообщений за запрос | По умолчанию |
| **По постам** | `messages.getReplies` для каждого поста с комментариями | История группы недоступна (приватная группа, нет членства) |

Режим «Авто» сначала пробует быстрый и сам переключается на «по постам», если быстрый не сработал.

**Дозабор** читает только сообщения новее прошлого сбора и дописывает их в основной сбор канала. Корни веток
запоминаются (`thread_roots`), поэтому учитываются и новые комментарии к старым постам. Неизвестные корни
запрашиваются по id.

## Чаты

- Индексатор читает историю от новых к старым через `messages.getHistory`, ~100 сообщений за запрос.
- «Обсуждение» сообщения — это тема у форумов и день у обычных групп.
- Участники берутся из `channels.getParticipants`. Большие группы отдают не больше ~10 000 участников.
  Если админы скрыли список, придут только админы.
- Сервисные сообщения и анонимные админы не учитываются.

## Каналы пользователей (поиск ТГК и чатов)

Для каждого человека в базе панель запрашивает полный профиль (`users.getFullUser`) и забирает из него:

1. **Личный канал**, закреплённый в профиле (`personal_channel_id`).
2. **Ссылки из bio**: `t.me/name`, `telegram.me`, `telegram.dog`, `name.t.me`, `t.me/+invite`,
   `t.me/joinchat/…`, `tg://resolve`, `tg://join`.
3. **Упоминания `@name` из bio.** Каждое имя проверяется через `contacts.resolveUsername`. В список
   попадают только каналы и чаты, люди и боты отсеиваются.
4. **Каналы, от имени которых люди пишут** в комментариях. Отдельных запросов для них не нужно.

Кроме профилей, поиск смотрит и на сами источники (каждый шаг можно отключить в параметрах запуска):

5. **Откуда репостят.** Сборщики запоминают у каждого сообщения канал, из которого оно переслано
   (`fwd_from`), то же для собранных постов. Запросов к Telegram не нужно.
6. **Упоминания в сообщениях и постах:** `@name` и t.me-ссылки. Их много, а каждое новое имя стоит
   `contacts.resolveUsername`, поэтому за запуск проверяются только самые упоминаемые (по умолчанию 100),
   остальные дождутся следующего запуска. Уже проверенные имена берутся из кэша.
7. **Похожие каналы** — рекомендации самого Telegram (`channels.getChannelRecommendations`) для
   каждого канала-источника, один запрос на канал.

Приватные инвайт-ссылки проверяются через `messages.checkChatInvite`: так видны название и число участников,
вступать при этом не нужно. Для найденных каналов отдельно запрашиваются описание и размер (`channels.getFullChannel`).

### Лимиты Telegram

У Telegram отдельный лимит на каждый метод. Больше всего страдает `contacts.resolveUsername`: после ~200
запросов подряд он может быть заблокирован на несколько часов.

- Блокировка учитывается **по виду запроса**: resolve, full_user, invite и full_channel.
  Пока заблокирован resolve, профили, инвайты и описания каналов продолжают собираться.
- Блокировки хранятся в базе и показываются в интерфейсе, следующий запуск их учитывает.
  Пропущенное не помечается проверенным: его доберёт запуск после окончания блокировки.
- Результаты кэшируются: username, который уже проверяли, повторно не запрашивается.
- Транспортная ошибка `429` (`InvalidBufferError`) обрабатывается так: короткие паузы 30/60/120 с,
  потом этот вид запроса паркуется на 15 минут.

## Посты каналов: через аккаунт или без него

Инструмент «Посты каналов» собирает посты с текстом, просмотрами, ссылками и пометкой репоста. Способ
выбирается при запуске:

- **Через аккаунт** (`messages.getHistory`): любой канал, который видит аккаунт, точные просмотры,
  число репостов и комментариев, id канала-первоисточника.
- **Без аккаунта** — через публичную веб-версию `t.me/s/<name>`, которую Telegram отдаёт браузерам.
  Работает только для публичных каналов с username и включённым превью, не тратит лимиты аккаунта.
  Просмотры там округлены (`1.2K`), репостов и комментариев нет, первоисточник репоста виден по
  username. Числовой id канала берётся из служебного атрибута поста, поэтому посты из обоих способов
  складываются в один канал. Между страницами по 20 постов делается пауза 1,5 с.

В тексте поста ищется маркировка рекламы: токен `erid` (в тексте или в ссылках) и формула «Реклама.
ООО …, ИНН …». ИНН проверяется по контрольной сумме.

## Контакты, ИНН и ЕГРЮЛ

Из bio, сообщений человека, описания канала и постов вытаскиваются телефоны (библиотека
`phonenumbers`, номера без кода страны считаются российскими), email, сайты, адреса кошельков
(TON, ETH/ERC-20, TRON/TRC-20, BTC), ИНН и ОГРН. ИНН и ОГРН берутся только рядом со словами «ИНН» /
«ОГРН» и с верной контрольной суммой — голые 10–12 цифр слишком часто оказываются чем-то другим.

По ИНН или ОГРН можно запросить карточку из ЕГРЮЛ/ЕГРИП: название, ОГРН, КПП, дату регистрации,
руководителя, регион, ликвидацию. Запрос идёт в публичный поиск `egrul.nalog.ru`, ответ кэшируется
на 30 дней.

## История профилей и возраст аккаунта

При каждом сборе имя, фамилия, username, фото, телефон (и bio при поиске каналов) сравниваются с
прошлым значением, изменения пишутся в историю профиля. Первое появление и неполные «min»-профили
из чатов изменениями не считаются.

Telegram выдаёт ID пользователей по порядку, поэтому дату регистрации можно оценить по опорным точкам
«ID → дата» (данные проекта [GetIDs](https://github.com/AmanoTeam/python-getids), MIT). Точки
заканчиваются в 2021 году: для более новых аккаунтов показывается «после 10.2021» и граница «не
позже» — самая ранняя активность людей с ID не меньше этого в вашей базе. Для каналов, в которых
аккаунт не состоит, Telegram сообщает дату создания напрямую.

## Username на других сайтах

По кнопке в профиле панель проверяет тот же username на ~600 публичных сайтах по базе
[WhatsMyName](https://github.com/WebBreacher/WhatsMyName) (CC BY-SA 4.0): один запрос к странице
профиля на каждом сайте, без Telegram-аккаунта. Сайты для взрослых и знакомств исключены. Часть сайтов
закрыта от автоматических запросов — они не считаются ни найденными, ни отсутствующими. Совпадение
имени не доказывает, что это тот же человек.

## FloodWait и остановка

- FloodWait до 60 с переживается молча (в оптимизированном профиле — до 120 с).
- Более длинные паузы показываются в интерфейсе обратным отсчётом, потом задача продолжает с того же места.
- Если задачу остановить, всё собранное к этому моменту сохраняется.
- В раннере одновременно выполняется одна задача на аккаунт, остальные ждут в очереди.

## Профиль нагрузки

В **Настройки → Нагрузка на Telegram** выбирается, насколько интенсивно панель работает с Telegram. Профиль
действует на все аккаунты и все инструменты: каждый запрос проходит через общий ограничитель аккаунта.

| | Стандартный | Оптимизированный |
|---|---|---|
| Пауза между любыми запросами | 0 | 0,3 с |
| Чтение сообщений и участников (страница = 100 сообщений) | 0 | 1 с |
| Тяжёлые запросы: ResolveUsername, полные профили, инвайты, похожие каналы | 0 | 3 с |
| Части файлов (аватарки) | 0 | 0,3 с |
| Случайный разброс пауз | — | до +30% |
| Пережидать FloodWait до | 60 с | 120 с |
| Аватарки параллельно | 3 | 2 |
| Пауза между задачами одного аккаунта | 0 | 20 с |
| «Каналы пользователей»: проверок за запуск / перепроверка через | 500 / 7 дн | 200 / 14 дн |
| Страницы t.me/s (без аккаунта) | 1,5 с | 2,5 с |
| Адаптивное замедление | нет | да |

*Адаптивное замедление*: после FloodWait запросы того же типа идут с дополнительной паузой, которая удваивается
с каждым новым FloodWait (до минуты). После 15 минут без ошибок пауза снимается.

«Свои настройки» открывают все параметры. Под ними журнал FloodWait за сутки по методам: если в нём
растёт `ResolveUsername`, увеличьте паузу тяжёлых запросов; если `GetHistory` — паузу чтения.

Работает в любом профиле:

- одна задача на аккаунт одновременно;
- найденные @username и access hash запоминаются, повторно их не ищут;
- аватарки по уже скачанному `photo_id` не качаются второй раз;
- проверенные профили не перечитываются без «перепроверки».

## Аватарки

- Качаются только недостающие: кэш по `photo_id`.
- Недоступные запоминаются на сутки.
- У каждой загрузки есть тайм-аут.
- Этап можно пропустить.

## Что собирается

Только то, что видно подключённому аккаунту: публичные каналы, группы, где он состоит, публичные профили.
Телефоны почти всегда скрыты настройками приватности, и панель их не ищет.
